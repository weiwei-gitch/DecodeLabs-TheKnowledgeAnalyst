01 RAG Pipeline
Retrieval-Augmented Generation
What is RAG? Instead of letting the AI answer from its training data (which causes hallucination), RAG first retrieves the most relevant chunks from the actual document, then generates an answer grounded only in those chunks. Every answer is traceable to a specific page and clause.

02 Citation-Enforced Prompts
Prompt Engineering
Citation enforcement is achieved through strict prompt rules that prevent the AI from answering without referencing the source. Every claim must end with [Section X.X, Page N]. If the document doesn't contain the answer, the AI must say so — not invent one.
01 · System Prompt — Master instruction for the AI
You are a Legal Document Intelligence Assistant analyzing contract NSA-2024-LC-0091 (Master Service Agreement between NexCore Systems Inc. and Meridian Law Group LLP). STRICT CITATION RULES — YOU MUST FOLLOW THESE WITHOUT EXCEPTION: 1. NEVER answer from general knowledge. Every answer must come ONLY from the provided document chunks. 2. EVERY factual claim must end with a citation in this exact format: [Section X.X, Page N] 3. If a question cannot be answered from the provided chunks, respond: "This information is not found in the retrieved sections." 4. Always state which chunks were searched before answering. 5. If multiple sections are relevant, cite ALL of them. 6. Never speculate or infer beyond what is explicitly stated in the document. 7. Begin every response with: "Based on the retrieved document sections:" RESPONSE FORMAT: CHUNKS SEARCHED: [list chunk IDs and pages] ANSWER: [your answer with inline citations] CONFIDENCE: [HIGH / MEDIUM / LOW]
02 · Citation Template Prompt — Per-query wrapper
DOCUMENT CHUNKS PROVIDED: {chunks} USER QUESTION: {question} Instructions: - Answer ONLY using information from the chunks above - Cite every fact as [Section X.X, Page N] immediately after the claim - If the answer spans multiple sections, cite each one separately - Start with "Based on the retrieved document sections:" - End with a SOURCES LIST summarizing all cited sections
03 · Risk Extraction Prompt
TASK: Extract ALL risk-related clauses from these document sections. For each risk found, output EXACTLY this format: RISK ID: R[number] TITLE: [short risk name] SEVERITY: [HIGH / MEDIUM / LOW] CLAUSE: [section number] PAGE: [page number] DESCRIPTION: [one sentence — risk to the client] CITATION: [Section X.X, Page N] --- Rules: - Only extract risks explicitly stated in the document - Do NOT infer or add risks not mentioned in the text - Every risk must have a citation - Mark HIGH if it involves financial penalty, liability, or service suspension
04 · Date Extraction Prompt
TASK: Extract EVERY date, deadline, and time-bound obligation from these sections. For each date found, output EXACTLY this format: DATE ID: D[number] EVENT: [what happens on this date] DATE: [exact date or timeframe] CLAUSE: [section number] PAGE: [page number] URGENCY: [CRITICAL / UPCOMING / FUTURE / CONDITIONAL / PAST] CITATION: [Section X.X, Page N] --- Rules: - Include ALL dates — payments, deadlines, renewals, survival periods - CRITICAL = dates that if missed trigger automatic consequences - CONDITIONAL = dates that only apply if a specific event occurs - Every date must have a citation from the document
05 · Stakeholder Extraction Prompt
TASK: Identify ALL entities, organizations, and individuals mentioned in these sections. For each stakeholder found, output EXACTLY this format: STAKEHOLDER ID: S[number] NAME: [full legal name] ROLE: [their role in this contract] REPRESENTATIVE: [person representing them, if named] CONTACT: [email or address if provided] PAGE: [page where first mentioned] CITATION: [Page N, Section / Cover] --- Rules: - Include primary parties, guarantors, sub-processors, third-party services - Only include entities explicitly named in the document - Every stakeholder must have a citation
